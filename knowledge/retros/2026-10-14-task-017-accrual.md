# Retro — TASK-017 monthly accrual (2026-10-14)

Scope: `accrual_ledger` migration, `runAccrual` (one SQL statement), `GET`/`POST /api/jobs/accrual`, `vercel.json`
(`0 0 1 * *`), ADR-LeaveTrack-E002, a "last accrual" line on the balance page. Verified with the full gate (149 tests, build
pending, see below), a real Postgres 18 (20 checks through the real SQL and routes, run twice, harness deleted, throwaway
database dropped), and the migration and seed applied twice plus `verify_schema.sql` on a fresh database. No product defect
found. Two harness mistakes were fixed along the way (a wrong expected total, and a setup order that gave a test user a
balance row); neither was a code bug.

## Decisions taken (confirmed with the user by approving the plan)

- A per-employee, per-leave-type, per-month **ledger** (not one row per month), so late joiners and history work.
- **Catch-up** of missed months (Vercel does not retry); the first ever run accrues the current month only (no back-pay).
- A missing balance row is **created holding exactly the accrued amount** (0 + accrual). Approval is different: it never
  creates a row (TASK-014).
- Route answers **GET** (Vercel Cron) and **POST** (manual runs and the original spec). The CSV and architecture docs said
  POST only; Vercel's docs say it calls with GET.

## Pattern worth reusing

- **Idempotent job as one SQL statement:** insert the due ledger rows with `ON CONFLICT DO NOTHING ... RETURNING`, then
  apply the effect only from the rows the ledger accepted. Atomic, and concurrent runs queue on the unique key (5
  simultaneous runs credited once; an accrual racing an approval 15 times never lost an update).
- **`generate_series(date, date, interval)` returns `timestamptz`**, so its output depends on the session time zone. Cast the
  inputs to `timestamp` first. Verified with Pacific/Kiritimati, America/Los_Angeles and Asia/Manila.
