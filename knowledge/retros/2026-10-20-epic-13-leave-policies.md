# Retro: EPIC-13, Leave Policies (TASK-070 to 073)

Built and validated locally, **not committed, not pushed**. One new migration (`20261020120000_leave_policy_changes.sql`), so **a push needs the migration on staging before the code that writes the history** (CI's `db-push` applies it on a push to `main`, but Vercel can deploy first: watch the Actions run; the page and the rate edit work without the table, only the "Recent changes" card and a save's change record do not). No role, required-feature or `docs/` change except the new `docs/dev-tasks/epic-13-leave-policies-tasks.csv` (status `Open`: not marked `Done`). Decided with the user on 2026-10-20 as the replacement for EPIC-8, which is deferred.

## Why

The PRD role list says the HR Admin "configures leave policies" and the BRD says policies are configured by HR, not self-service, but no user story or acceptance criterion describes a screen, and the app had none: the only way to change an accrual rate was SQL. The seed gives each employee 1.25 days a month Vacation and 1.00 Sick; the monthly accrual job (`accrual.ts`, unchanged) reads `leave_policies`.

## What shipped

- **Table `leave_policy_changes`** (append-only like `accrual_ledger`; RLS on, no policy): employee, leave type, who changed it, old rate (null for a first policy), new rate bounded 0 to 31, when. A change must change the rate. `verify_schema.sql` counts 9 tables and RLS on 9 and probes every rule; `types.ts` mirrors it; an ungated test pins the 31 in the migration to `POLICY_RATE_MAX`.
- **Reads** (`src/lib/leave/policies.ts`, one statement each, HR only in the SQL): `getPolicyPage` (employees only, Vacation then Sick, literal name search, 25 a page, the total counted before the cut and the page clamped in SQL) and `getRecentPolicyChanges` (the latest 10, cut to ten from the change table alone before the names are joined).
- **Write** `PUT /api/leave-policies` (`withErrorHandling`, zod, `assertRole("hr_admin")`, `no-store`) and `setPolicyRate`: one transaction of three statements: an advisory lock on (employee, type), the checks decided in SQL (actor is `hr_admin`, target is an `employee`, the type tracks a balance, plus the current rate), then the rate and its change row in ONE statement. An unchanged rate writes nothing. A manager, an HR Admin, Unpaid and an unknown id all give the same not-found. A documented exception to AGENTS.md rule 3 (HR's scope is the company); the one-sentence note in `AGENTS.md` was **not added** (needs the user's OK).
- **Page `/policies`** (HR only; employees and managers are sent to the dashboard): a search box (plain GET form), a row per employee with a labelled rate field and Save per type ("No policy yet" when none), pages of 25, "Recent changes", and a note that a new rate applies from the next monthly accrual. A white "Leave Policies" nav item for HR only, between Calendar and Audit History. Two statements per page load. The demo checklist now lists it.

## Behaviour to state plainly

- **A new rate applies from the next accrual run.** A month already in `accrual_ledger` is never rewritten and nothing is paid back (proven through the real accrual). A policy created for someone who had none is credited for the CURRENT month on the next run, once (also proven).
- **Only employees** are listed and editable. Old policy rows of managers and HR Admins on staging still accrue and the page cannot show or fix them (the existing backlog item).

## Found and fixed during validation

- **[FIX NOW] "Recent changes" joined every change before cutting to ten**, so it would have slowed for ever as the append-only history grows (a hash join over all rows at 1,600). It now picks the newest ten from `leave_policy_changes` alone (incremental sort on `changed_at`), then names them: 0.3 ms at 100,021 change rows. Found by reading the EXPLAIN, not by a test.
- **[FIX NOW, test] The lock test did not prove the lock** (removing it still passed 6 of 6 runs; only a unit test noticed). It now holds the advisory lock in another transaction and asserts the write waits.
- Harness slips only: the header's user name made a "never lists HR" check fail at wide widths, a cleared number field kept its React state, and a request-interception handler outlived its switch.

## Not seen

Real Supabase and staging (the migration has not reached staging), GitHub Actions and Vercel, a screen reader. The gated tests do not run in CI.

## Backlog (nothing blocking)

- No bulk "set a default rate for everyone"; 800 employees are edited one at a time. A per-person "Save both" would halve the clicks.
- Accrual still credits the old policies of managers and HR Admins on staging and the page cannot show them.
- A new person's policy row still has to be added, by HR on this page (a person with none shows "No policy yet") or by SQL; adding people is EPIC-8 (deferred).
- The change record says who and when but not why (no note field).
- The list is a sequential scan of `users` filtered by role; fine at 2,000, re-check at orders of magnitude more.

## Phase 1 redesign for many employees (TASK-074, same day, after the first validation)

Built and validated locally, **not committed, not pushed**. UI and reads only: **no migration**, no new route, no role or required-feature change. From the user's ChatGPT mockup (image pasted in the chat; not in the repo). The first card-per-employee page worked for three people and would have been about 25 screens per page for 25 employees; it is now a table.

### What shipped

- **Reads** (`policies.ts`, still one statement each, HR only in the SQL): `getPolicyPage` gains the page size (25, 50, 100), a sort (name, Vacation rate, Sick rate, last changed, each either way; empty rates and "never changed" always last; name then id as the tie-break), filters (team = a manager's employees, leave type, status: no policy yet = a shown rate is missing, has a policy, changed this month), each person's manager and newest change (when and by whom), and a company-wide `summary` for the three tiles (it ignores the search and filters). The order is a `CASE` over bound values (`policies-schema.ts` validates `sort` against a fixed list), never text. New `getPolicyChoices` (managers with employees, accruing leave types) for the filters. `setPolicyRate` also returns `changedAt` and `changedByName`. The recent list is 5. The page is three statements (list, choices, recent).
- **Page:** three tiles (the "no policy" and "changed this month" tiles link into the filter); a search and filter card (name, Team, Leave type, Status, Sort by, Rows per page; a select applies as soon as it changes, with removable chips and "Clear all", every change back to page 1, a no-script Apply button; the five selects sit behind a "Filters and sort" button on a phone unless a filter is applied); the employees as a real table from 1280 px (sticky header, sortable column links with `aria-sort`, the employee as the row header, the manager under the name, Last changed as "date by who", a status badge) and as stacked cards below; in-cell editing (Enter or leaving the field saves, Esc reverts, saving, saved and error states, announced); a numbered pager; Recent changes beside the list from 1700 px and under it below.
- **One shared state for both structures** (`PolicyTable`): the table and the cards are the same cells, so an edit shows in both and a hidden copy is `display:none` (never focusable). Rows are taken from the server **once per address** and kept in state: a save updates its row in place, so the row neither moves (a list sorted by that rate) nor disappears (a filtered list); only the tiles and Recent changes are refreshed (`router.refresh()`).
- Left out on purpose (phase 2): row checkboxes, the bulk bar and "Select all N matching", "View all history", the "⋮" menu, and the mockup's other sidebar icons and sample names.

### Found and fixed during validation

- **[FIX NOW, found by the gated tests] Every sort except name A to Z was ignored.** The page's final `json_agg` ordered by name and undid the order chosen in the CTE. The order is now carried as a row number and the aggregate uses it.
- **[FIX NOW, found by the browser run crashing] A refreshed list moved or removed the edited row.** After a save the server sends fresh rows; the table rendered from those props, so in a list sorted by rate or filtered to "No policy yet" the row jumped or vanished at once, without its "Saved". The rows are now taken once per address and kept in state, with a guard test (the rows must come from state) and its mutation.
- **[FIX NOW, from the screenshots]** the "No policy yet" badge and the header labels wrapped on a 1536 px screen and the table was cramped beside the aside: the badge no longer wraps, the unit ("days/month") sits under the rate name, the aside moved from 1536 to 1700 px, the five selects share one row from 1280 px, and on a phone the tiles are three small columns and the selects collapse so the first employee is on the first screen.
- A react-hooks lint error (a ref written during render) was fixed by updating the ref in an effect.
- Harness slips only: the avatar's initials were read as the name, a 1 px border counted against the sticky header, and a dirty database after edits.
